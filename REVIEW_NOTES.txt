APPLICATION REVIEW NOTES

This review package includes the existing Event Management System source code and database.
The Windows startup script now checks that Python and npm are available and displays clearer
messages if a required tool is missing.

Checks completed in this environment:
- Python source files compile without syntax errors.
- SQLite database integrity check passes.
- ZIP archive integrity passes.
- Existing event records and booking data were preserved.

Checks not completed:
- Django system checks and backend tests could not run because Django is not installed in this
  environment and dependencies could not be installed here.
- React production build could not run because frontend node_modules are not included.
- Email delivery, Google sign-in, booking flows, and browser behavior need to be tested locally.

Beginner setup:
1. Install Python 3 and Node.js LTS (includes npm).
2. Extract the ZIP.
3. Double-click START_PROJECT.cmd.
4. Keep both terminal windows open while using the app.
5. Open http://127.0.0.1:5173/.

Back up backend/db.sqlite3 before making further changes.

Payment-gated QR ticket update:
- The booking API now returns a ticket token only when the booking is confirmed/attended and its payment status is successful.
- The attendee booking page checks both booking status and payment status before rendering the QR code or allowing ticket printing.
- Pending, failed, expired, and cancelled bookings show a locked ticket panel instead.
- Added a regression assertion to the QR check-in test for pending bookings and refreshed booking data after payment.
- Free events retain their immediate confirmed registration because the backend records their zero-cost payment as successful.


Reservation timing update (28 October 2026): unpaid reservations now have a 15-minute payment window. The backend expiry cutoff, payment endpoint, expiry notification, management-command description, event details message, and on-screen countdown use the same 15-minute duration. QR tickets remain unavailable until payment is successful.

Frontend dependency fix (28 October 2026)
- Fixed the TicketScanner build error by keeping html5-qrcode declared in frontend/package.json and removing the stale package-lock.json that did not include this dependency. The startup script runs npm install, which will now generate a consistent lockfile and install html5-qrcode.
- If starting manually, run `npm install` inside the frontend folder before `npm run dev`.

QR ticket expiry and single-use update:
- QR tokens are returned only for successfully paid, confirmed bookings before the event end time.
- A successful check-in marks the booking attended; the token is then withheld from attendee booking responses.
- Repeat scans are rejected, and scans after the event end time are rejected.
